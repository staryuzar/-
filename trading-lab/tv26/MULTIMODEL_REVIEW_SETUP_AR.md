# إعداد المراجعة المستقلة متعددة النماذج — TV26

## ما الذي أُضيف؟
- `.github/workflows/tv26-independent-multimodel-review.yml`: سير عمل يدوي فقط؛ لا يعمل مع كل عملية دفع ولا يغيّر ملفات المستشار.
- `trading-lab/tv26/run_independent_reviews.py`: يرسل ملفات المصدر المحددة فقط إلى مزوّدي المراجعة الرسميين، ويحفظ كل مراجعة كأثر مستقل.
- لا يجري هذا السير أي صفقة أو اختبار تداول، ولا يقرأ بيانات دخول MT5 أو تقارير الحساب أو ملفات التاريخ. ولا يكتب إلى المستودع أو يدمج تغييرات.

## تفعيل المزوّدين
أضف مفاتيح API بنفسك من إعدادات مستودع GitHub، ولا تلصقها في المحادثة أو في ملفات المصدر:

1. افتح مستودع `staryuzar/-` ثم **Settings → Secrets and variables → Actions**.
2. أنشئ واحدًا أو أكثر من Repository secrets بالأسماء الدقيقة:
   - `ANTHROPIC_API_KEY` لمزوّد Claude.
   - `DEEPSEEK_API_KEY` لمزوّد DeepSeek.
   - `GEMINI_API_KEY` لمزوّد Gemini.
3. تحتاج إلى مفتاح صالح وفوترة/حصة متاحة لدى المزوّد نفسه. لا يُنشئ GitHub هذه المفاتيح تلقائيًا.
4. افتح **Actions → TV26 independent multi-model code review → Run workflow** على الفرع `tv26-exit-diagnostic-study`.
5. اختر نطاق المراجعة: `full` أو `exit-path` أو `tradingview-parity`.
6. نزّل الأثر `tv26-independent-review-<run-id>` واقرأ `SUMMARY.md` ثم تقارير كل مزوّد.

## الخصوصية وحدود الثقة
- عند التشغيل، تُرسل نسخة من ملفات المصدر المختارة إلى كل مزوّد فعّال عبر API الخاص به. لا تشغّل المراجعة إلا إذا كنت موافقًا على مشاركة هذه الشيفرة مع المزوّدين الذين ضبطت مفاتيحهم.
- لا تُرسل مفاتيح API نفسها ضمن نص الطلب؛ يستخدمها الاتصال في ترويسة/عنوان API حسب متطلبات المزوّد.
- كل مراجعة رأي مساعد وقد تخطئ أو تختلق مراجع؛ يجب التأكد من موضع كل عيب واختباره قبل تعديل المستشار.
- نجاح مراجعة الشيفرة لا يثبت مطابقة TradingView ولا ربحية المستشار. تبقى المقارنة الرقمية مع CSV الحقيقي من TradingView واختبارات MT5 المستقلة بوابات منفصلة.
- لا يوجد تفعيل تلقائي للتداول الحقيقي، ولا دمج تلقائي، ولا تعديل تلقائي للمصدر.

## استكشاف الأخطاء
إذا لم تُضف أي أسرار، سينشئ التشغيل ملف `SETUP_REQUIRED.md` ويفشل برسالة واضحة. إذا فشل مزوّد واحد، تُحفظ رسالة الخطأ ويحاول البرنامج بقية المزوّدين؛ لا يعتبر التشغيل ناجحًا إلا إذا عاد تقرير واحد على الأقل بنص.
