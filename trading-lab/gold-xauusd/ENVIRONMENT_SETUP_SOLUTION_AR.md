# تجهيز GitHub لتطوير واختبار مستشار GoldLab

## مساران للعمل
1. **Environment Preflight:** يثبت MT5 في جلسة Windows مؤقتة، يتحقق من وجود Terminal وMetaEditor، ثم يجمع EA دخانياً مستقلاً للتأكد من أن المترجم يعمل. لا يحتاج هذا الفحص بيانات الحساب ولا يشغل استراتيجية الذهب.
2. **Advisor OrderCheck Execution Safety:** هذا هو اختبار المستشار الفعلي. عند تعديل مصدر المستشار أو مشغل المختبر في الفروع المرشحة، يجمع GoldLabEA باستخدام MetaEditor ثم يشغل MT5 Strategy Tester بنموذج كل حركة اعتماداً على ticks الحقيقية المتاحة، مستخدماً سر GitHub Actions `mt5`. يحفظ تقرير MT5 والسجلات وتحليل سلامة أوامر التداول كـ artifact.

## أسلوب التطوير
- عدّل ملفات MQL5 على الفرع `goldlab-request-result-candidate` فقط.
- تغييرات EA أو مشغل الاختبار تشغّل اختبار OrderCheck تلقائياً.
- راجع كل تشغيل في [GitHub Actions](https://github.com/staryuzar/-/actions) ونزّل ملفات artifact.
- لا تعتبر نجاح التجميع وحده نجاحاً للاستراتيجية. اربط كل نتيجة بمعرّف التشغيل وcommit SHA وبصمة المصدر، وتحقق من تقرير Strategy Tester ومن سجلات الطلبات.
- لا تخلط بين طلبات تعديل وقف الخسارة وصفقات الدخول الجديدة.

## بيانات الدخول
- اختبار المستشار الفعلي فقط يحتاج إلى GitHub Actions secret اسمه `mt5` بصيغة معتمدة من `.github/scripts/goldlab_mt5_test.ps1`.
- لا تضع بيانات الدخول أو كلمة المرور في المستودع أو التقارير.
- فحص البيئة لا يحتاج السر `mt5` ولا يحاول تسجيل الدخول.

## حدود البيئة
- `windows-2022` على GitHub-hosted runner جهاز افتراضي مؤقت يُنشأ لكل تشغيل ثم ينتهي؛ لا تبقى نافذة MT5 مفتوحة بين الجولات.
- الاختبار السابق اتصل بـ Headway-Demo أثناء تشغيل Strategy Tester، ثم انتهى الاتصال عند نهاية الجلسة.
- للحصول على جهاز دائم يحتفظ بتثبيت MT5 بين الجولات، يلزم Windows VM/VPS خاص وتشغيل self-hosted GitHub Actions runner عليه؛ ذلك يحتاج خادماً مستمراً لا يوفره المستودع وحده.
- فترة الاختبار المحجوزة 2026-10-21 إلى 2026-10-23 تبقى محمية حتى الموعد المسجل في سجل المشروع. لا تغير استراتيجية الذهب أو مدخلاتها ولا تختبر نافذة الحجز قبل فتحها.
