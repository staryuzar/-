# تثبيت Mirsad Chart Observer على MetaTrader 5

## ما هذه الإضافة؟

Mirsad Chart Observer خبير مستقل للقراءة فقط. يلتقط صورة PNG من المخطط المثبت عليه، ويأخذ معه بيانات OHLC من MT5، ثم ينشر الحزمة في مجلد Observer المشترك ليقرأها برنامج مرصاد.

- لا يفتح أو يغلق صفقات.
- لا يستقبل أوامر MIR1.
- لا يكتب إلى command.json أو ack.json أو status.json الخاص بخبير التنفيذ.
- يعمل على حساب تجريبي أو حقيقي ومع أي وسيط يدعم MT5.
- لا يحتاج إلى بيانات دخول الحساب عند تشغيله محلياً؛ يحتاجها فقط عند الاختبار عن بعد عبر GitHub Actions.
- لا يستورد DLL خارجياً.

المراقب مثبت على مخطط واحد في هذه النسخة، لكنه لا يقيّد نوع الحساب أو الوسيط أو قائمة الرموز أو أطر MT5 الزمنية.

## متطلبات التشغيل

- MetaTrader 5 على Windows.
- صلاحية تشغيل Expert Advisors على الطرفية.
- Python الخاص بمرصاد على الجهاز نفسه، أو برنامج آخر يستطيع قراءة مجلد Terminal\Common\Files.
- قيمة MIRSAD_MT5_COMMON_FILES مضبوطة على مجلد Common\Files نفسه.

## التجميع

1. افتح MT5 واختر File ثم Open Data Folder.
2. افتح MQL5 ثم Experts.
3. انسخ Mirsad_ChartObserver.mq5 إلى Experts.
4. افتح MetaEditor من MT5.
5. افتح الملف من Navigator أو File > Open.
6. اضغط Compile.
7. تحقق من نتيجة MetaEditor: 0 errors و0 warnings.
8. ارجع إلى MT5، وافتح Navigator، وانقر بزر الفأرة الأيمن على Expert Advisors واختر Refresh.

يوجد أيضاً سير تجميع آلي على GitHub Actions:
https://github.com/staryuzar/-/actions/workflows/mirsad-chart-observer-compile.yml

احتفظ بملف EX5 الناتج من البناء الذي اجتاز الاختبار. لا تستخدم نسخة من تشغيل فاشل أو قديم.

## إرفاقه بالمخطط

1. افتح أي مخطط تريد مراقبته، واختر الرمز والإطار المطلوبين من الوسيط.
2. اسحب Mirsad_ChartObserver إلى هذا المخطط فقط.
3. راجع الإعدادات:
   - Capture interval: 60 ثانية افتراضياً.
   - History bars: 120.
   - Screenshot: 1600×900.
   - Capture immediately: true.
4. لا تحتاج إلى تفعيل DLL imports.
5. لا تمنحه أي صلاحيات تداول إضافية؛ لا توجد في الكود دوال إرسال أوامر.
6. تحقق من تبويب Experts في MT5 بحثاً عن رسالة بدء المراقب وحالة الالتقاط.

يمكن تغيير فاصل الالتقاط وعدد الشموع وأبعاد الصورة. لا توجد قائمة أطر زمنية أو رموز ثابتة في المراقب؛ فهو يأخذ الرمز والفترة من المخطط نفسه.

## أين ستظهر الصور والبيانات؟

بعد نجاح الالتقاط والنقل:

Terminal\Common\Files\MirsadBTC\observer\

وتحتوي:
- observer_status.json: الحالة التشخيصية للخبير.
- capture_<id>.json: بيانات اللقطة والشموع.
- images\o_<id>.png: صورة المخطط.

لا تخلط مجلد observer مع ملفات تنفيذ MIR1 الموجودة في MirsadBTC مباشرة.

## ربط Python بمجلد MT5 المشترك

اضبط المتغير MIRSAD_MT5_COMMON_FILES على المجلد الذي يحتوي ملفات MT5 المشتركة، وليس على مجلد MirsadBTC أو observer.

مثال توضيحي:

MIRSAD_MT5_COMMON_FILES=C:\Users\<WindowsUser>\AppData\Roaming\MetaQuotes\Terminal\Common\Files

يستخدم Python المسار التالي داخلياً:

Common\Files\MirsadBTC\observer\

## ما الذي يثبت أن الالتقاط نجح؟

يجب أن ترى:
1. صورة PNG موجودة في مجلد images.
2. ملف capture_<id>.json مطابقاً لها.
3. عدد bars يساوي bars_copied.
4. الشموع مرتبة من الأقدم للأحدث.
5. آخر شمعة فقط تحمل is_closed=false.
6. قارئ Python يعيد READY_FOR_ENGINE_2_VALIDATION.
7. القرار يبقى decision_eligible=false في هذه المرحلة.

وجود READY_FOR_ENGINE_2_VALIDATION يعني أن الحزمة سليمة للنقل والفحص الأولي فقط، وليس أنها أصبحت صالحة لقرار BUY/SELL. ما زال على المحرك الثاني تحديد منطقة الرسم ومعايرة محوري السعر والزمن ومطابقة الشموع المرئية.

## تنبيه التخزين

الفاصل الافتراضي دقيقة واحدة ينتج ما يصل إلى 1440 لقطة في اليوم لكل مخطط، وكل لقطة تضم صورة وملف JSON. سياسة الاحتفاظ والتنظيف الآلي لم تكتمل بعد.

لذلك:
- ابدأ باختبار قصير ومراقب.
- لا تترك المراقب يعمل أياماً متواصلة قبل إضافة سياسة الاحتفاظ.
- لا تحذف الصور أو manifests التي لم يقرأها مرصاد بعد.
- لا تعتبر اختبار GitHub Actions دليلاً على أن جهازك المحلي يشغل MT5 أو يراقب المخطط باستمرار.

## حالة الإصدار

- تم إنشاء خبير MQL5 منفصل.
- تم إنشاء قارئ Python يتحقق من manifest وPNG وOHLC والحداثة.
- توجد اختبارات وحدات للبيانات الصحيحة والحالات المرفوضة.
- تم إنشاء سير تجميع على Windows/MetaEditor.
- تم التحقق من التقاط حي على GitHub Windows runner في تشغيلين متتاليين (#13 و#14): اتصال Headway Demo، صورة PNG بحجم 1600×900، و120 شمعة OHLC بحالة AVAILABLE. هذا لا يثبت التشغيل الدائم أو الالتقاط على Windows VM دائم.
- لم يتم ربط Observer بقرار Engine 4.
- لا توجد حالياً إدارة كاملة للاحتفاظ بالصور القديمة.

هذا الفصل مقصود: نثبت الالتقاط والنقل والتطابق أولاً، ثم نضيف المعايرة البصرية والزمنية، وبعدها فقط نوصله بمدخل المحرك الثاني.

## تشغيل اختبار الاتصال من GitHub على أي حساب MT5

يوجد Workflow يدوي: https://github.com/staryuzar/-/actions/workflows/mirsad-mt5-observer-demo.yml

يستخدم Workflow السر الموجود مسبقاً باسم mt5 في المستودع الحالي staryuzar/-. يقبل سكربت التشغيل صيغة السطرين الحالية (رقم الدخول في السطر الأول وكلمة المرور في الثاني)، كما يقبل JSON يحتوي login وpassword، ويمكن إضافة server وsymbol وtimeframe اختيارياً. لا حاجة لإنشاء سر جديد إذا كان السر نفسه مستخدماً بنجاح في اختبار الخبير الناقل. قيمة الخادم الافتراضية في Workflow هي العنوان التقني mt5.demo.trade-hw.online، وهو العنوان المستخدم في اختبار Headway Demo السابق الناجح؛ ويمكن تغييره من مدخل server عند الحاجة. إذا احتوى السر على server صريح فله الأولوية على مدخل Workflow.
 
للتوضيح: Headway-Demo هو اسم الخادم الظاهر للمستخدم، أما عنوان الاتصال التقني المستخدم في اختبار مرصاد السابق فهو mt5.demo.trade-hw.online. لا تضع كلمة المرور في مدخلات Workflow أو ملفات المشروع أو السجلات؛ تحفظ داخل GitHub Secret فقط. السر المحفوظ في مستودع آخر لا ينتقل تلقائياً إلى staryuzar/-.
 
لا توجد قائمة وسطاء أو حسابات محظورة؛ الاختبار يستخدم الحساب الذي تحدده. صلاحية التداول الآلي تبقى معطلة لأن المراقب للقراءة فقط، وطرفية GitHub مؤقتة وليست اتصالاً دائماً.
