# تقرير لوحة القيادة ومركز صحة المحركات — مرصاد BTC

**تاريخ المراجعة:** 4 نوفمبر 2026  
**المستودع:** `staryuzar/-`  
**فرع العمل:** `mini`  
**ملف الواجهة:** `Mirsad_BTC/dashboard.py`  
**بناء الصحة:** `Mirsad_BTC/mirsad/health.py`  
**مصدر الحالة:** `Mirsad_BTC/data/system_status.json`

## 1. النتيجة

لوحة Streamlit جزء من البرنامج نفسه وليست نموذجًا تجريبيًا منفصلًا. تقرأ أحدث حالة يكتبها `mirsad/runtime.py`، وتعيد عرضها كل **10 ثوانٍ** بواسطة `st.fragment(run_every=10)`. حالات بطاقات الصحة تستند إلى telemetry فعلية لا إلى وجود ملفات المصدر فقط.

تحتوي قائمة الصحة على **21 مكوّنًا مراقبًا** موزعًا على دورة التشغيل والمحركات الخمسة. وتعرض اللوحة أيضًا صفحات التحليل والقرار والتنفيذ وسجل المراكز.

## 2. معنى الحالات

| الحالة | المعنى |
|---|---|
| `HEALTHY` | يعمل فعليًا أو تم التحقق من الحالة |
| `WAITING` | ينتظر بيانات أو اتصالًا أو شرطًا لم يكتمل |
| `ATTENTION` | خطأ أو بيانات قديمة أو عدم تطابق أو رفض |
| `SAFE_DISABLED` | تعطيل مقصود للحماية أو التطوير |

لا تُرقّى البيانات المفقودة إلى نجاح. وإذا فشلت دورة runtime مع نبض حديث، تُعرض الحالة `ERROR` ويظهر نص سبب فشل آخر دورة عند توفره. ويظهر حفظ المعايرة كـ`STORED` أو `ALREADY_STORED` عند نجاحه، و`SKIPPED` عند عدم اكتمال شروط العينة، و`ERROR` عند فشل التخزين.

## 3. ما تعرضه اللوحة

### التشغيل
- الحالة العامة وعمر آخر نبض.
- سبب آخر فشل لدورة runtime إذا كتبه ملف الحالة.

### المحرك الأول — استخبارات السوق
- حالات مصادر الاستخبارات والأخبار والتقويم.
- Fear & Greed والسوق الكلي والتغطية والاتجاه السياقي.
- تقييم مخاطر السياق والعناوين والأحداث الاقتصادية.
- منصات المشتقات والتمويل وLong/Short وحداثة البيانات.
- أخطاء نقاط API للمشتقات حيث يوفرها المصدر، وحالات كل موجز إخباري.

### المحرك الثاني — الشموع وبنية السعر
- سجل OHLC الأصلي من MT5 عبر الأطر الزمنية الستة.
- عدد الشموع المغلقة وجودة البيانات واتجاه البنية ودرجة الدليل.
- سبب عدم الجاهزية، وتوافق الأطر، ونماذج الشموع وBOS/CHOCH والسيولة وFVG وOrder Blocks.
- لا تعتمد هذه النسخة على صور المخططات أو OCR لاتخاذ القرار.

### المحرك الثالث — المؤشرات
- قيم المؤشرات المحسوبة من شموع المحرك الثاني.
- تغطية التصويت والأطر والعائلات الناقصة.
- مقارنة CopyBuffer مع مؤشرات MT5 الأصلية، وعدد المقاييس الجاهزة وحالة المحاذاة وسبب الاختلاف.

### المحرك الرابع — القرار والمخاطر
- الإشارة المرشحة والقرار النهائي ودرجة التوافق والنتيجة المركبة.
- الأوزان الأساسية والفعالة المقروءة من `decision_weights` في دورة القرار؛ لا توجد نسب مكتوبة يدويًا في النص.
- سبب `WAIT` أو منع الدخول، وجاهزية الأمر، والدخول المرجعي والوقف والهدف.
- السبريد وانحراف السعر وحجم الصفقة والمخاطرة وحاجز الخسارة اليومية.
- حالة تخزين عينات المعايرة وسبب تخطيها أو فشلها.

### المحرك الخامس — MT5 والجسر
- حالة الجسر وعمر النبض وسعر Bid/Ask وهوية الرمز.
- بوابة نشر MIR1 ومفتاح تنفيذ الخبير.
- الأمر الحالي وACK ومصالحة ACK مع لقطة مراكز لاحقة.
- المراكز المفتوحة ودفتر صفقات مرصاد ودورات المراكز وصافي التدفقات ضمن حدود التاريخ المتاح.

## 4. مركز أوامر التنفيذ

يتضمن تبويبات أوامر MIR1 والتحكم، معاينة الأمر والإرسال، الحساب ومواصفات الرمز، المراكز المفتوحة، الإقرارات والمصالحة، سجل الأحداث، وإعدادات النظام والحدود.

لا تنشئ اللوحة إشارة سوق يدوية بديلة ولا تتجاوز بوابات المحرك الرابع. و`SUBMITTED` لا تعني أن الوسيط نفّذ الصفقة؛ تُنتظر مطابقة الإقرار مع نبضة ومراكز MT5 اللاحقة.

## 5. تصحيحات هذه المراجعة

1. استُبدل نص الأوزان القديم `20/50/30` بعرض القيم الفعلية التي يرسلها المحرك الرابع (ملف v6: `20/55/25`).
2. لم يعد النبض الحديث يخفي فشل دورة runtime؛ الخطأ يظهر كتنبيه، مع رسالة الخطأ إن توفرت.
3. أضيفت حالة حفظ أدلة معايرة القرار إلى مركز الصحة، مع التمييز بين الحفظ الناجح والتخطي والخطأ.
4. أضيف فحص آلي لتشغيل Streamlit وطلب `/_stcore/health` والصفحة الرئيسية دون اتصال MT5 أو إرسال أمر تداول.

## 6. الاختبارات وحدودها

- اختبارات مكوّن الصحة: **8 اختبارات** تشمل نقص OHLC والبيانات القديمة وأسباب عدم الجاهزية ودفتر الصفقات وأخطاء runtime وفشل تخزين المعايرة.
- مجموعة البرنامج الكاملة اجتازت **401 اختبارًا** في آخر دورة قبل إضافة فحص تشغيل Streamlit.
- نتيجة اختبار تشغيل الواجهة تُعتمد من خطوة `Smoke-test Streamlit dashboard and health endpoint` في آخر قبول شامل؛ لا تُستنتج من نجاح اختبارات الوحدات وحدها.
- اللوحة تعرض كل ما يكتبه runtime في telemetry، لكنها ليست مصححًا عامًا لكل سطر برمجي. إذا لم يرسل مزود خارجي سببًا تفصيليًا، قد يظهر رمز الحالة أو نوع خطأ HTTP فقط.

## 7. تشغيل اللوحة على Windows

من داخل مجلد `Mirsad_BTC` وبعد إنشاء البيئة الافتراضية وتثبيت `requirements.txt`:

```powershell
python run_mirsad.py
```

وفي نافذة ثانية:

```powershell
streamlit run dashboard.py
```

الأول يشغّل دورة جمع البيانات والمحركات؛ والثاني يعرضها. اللوحة لا تشغّل محركات التداول بذاتها، بل تقرأ حالة runtime.
