# البحث الخارجي للمحرك البصري — مرصاد BTC
**تاريخ البحث: 2 نوفمبر 2026**

هذا الملف يسجل مشاريع وأبحاثاً مفتوحة المصدر راجعنا صفحاتها وملفات README وبيانات مستودعاتها. الغرض الاستفادة من المكونات المناسبة، لا استيراد مشاريع كاملة أو تصديق وعود الأداء غير المقاسة على بيانات مرصاد.

## 1) مرشح عملي لبيانات تعريف صورة TradingView

### StephanAkkerman/chart-extractor
- الرابط: https://github.com/StephanAkkerman/chart-extractor
- الترخيص المعلن: MIT.
- آخر دفع للمستودع وفق GitHub API: 2 سبتمبر 2026.
- وظيفته محددة: كاشف YOLO يحدد صندوق عنوان الرسم وصندوق سعر آخر تداول (price pill)، ثم RapidOCR يقرأ النص ويحوّله إلى رمز/بورصة/فاصل زمني/سعر/جلسة.
- المشروع يذكر أن الهدف الأساسي صور TradingView وأنه يستخدم RapidOCR محلياً.
- اعتماداته تشمل rapidocr-onnxruntime وonnxruntime وOpenCV وNumPy وultralytics وhuggingface_hub. لدينا بالفعل RapidOCR/ONNX/OpenCV/NumPy، لكن إدخال YOLO/Hugging Face يضيف اعتماداً وأوزان نموذج جديدة.
- عدد النجوم في GitHub API وقت البحث كان 1؛ لم نجد في README قياساً مستقلاً منشوراً لدقة الاستخراج على BTC أو على لقطات مرصاد.

**قرار مرصاد:** أفضل مرشح لتجربة لاحقة لتقليل الإدخال اليدوي للرمز والفاصل الزمني وسعر آخر تداول. لم نضفه إلى المتطلبات ولم نجعله شرطاً لتشغيل المحلل؛ نحتاج أولاً مجموعة صور TradingView من بيئة مرصاد لقياس detection وOCR ومعدل الامتناع. ولا يجوز استخدام السعر المقروء من الشارة كبديل عن معايرة محور السعر.

### StephanAkkerman/chart-info-detector
- الرابط: https://github.com/StephanAkkerman/chart-info-detector
- الترخيص المعلن: MIT.
- وصف المستودع يحدد هدفه بكشف عنوان الرمز وصندوق السعر الأخير تحديداً.
- هذا نموذج كشف لمناطق metadata، وليس كاشف أجسام/ظلال الشموع ولا نموذجاً لفهم بنية السوق.

**قرار مرصاد:** يمكن لاحقاً استخدامه كطبقة metadata اختيارية، ولا يعالج عنق الزجاجة الأساسي في استخراج الشموع.

## 2) أبحاث استخراج الرسوم العامة

### ChartOCR / DeepRule
- الورقة: https://openaccess.thecvf.com/content/WACV2021/html/Luo_ChartOCR_Data_Extraction_From_Charts_Images_via_a_Deep_Hybrid_WACV_2021_paper.html
- الشيفرة: https://github.com/soap117/DeepRule
- الترخيص المعروض في المستودع: BSD-3-Clause.
- المنهج يجمع كشفاً بصرياً عميقاً مع قواعد هندسية، ويستخرج مكونات/نقاطاً رئيسية ثم يطبق قواعد خاصة بنوع الرسم.
- مستودع DeepRule الحالي يشترط GPU وCUDA وتجميع طبقات corner-pooling، ولذلك ليس اعتماداً خفيفاً لإضافته إلى تشغيل مرصاد الحالي.
- الورقة تتناول الرسوم البيانية العامة؛ لا تثبت وحدها دقة تحويل شموع التداول إلى OHLC.

**قرار مرصاد:** نستفيد من البنية الهجينة: كشف/تجزئة بصري للنقاط والأجزاء + قواعد OHLC ومعايرة. لا نستورد DeepRule بكامل اعتماده؛ نطور كاشف شموع متخصصاً ببياناتنا ثم نقيسه على الصور الفعلية.

### DePlot / UniChart / ChartQA
- DePlot: https://github.com/google-research/google-research/tree/master/deplot
- UniChart: https://github.com/vis-nlp/UniChart
- ChartQA: https://github.com/vis-nlp/ChartQA
- هذه الأعمال تركز على فهم المخططات العامة، وتحويل الرسم إلى جدول، والإجابة عن أسئلة تتطلب استدلالاً بصرياً/رقمياً. صفحة ChartQA تشير إلى UniChart كنموذج خفيف نسبياً (140M parameter) لمهام ChartQA وChart-to-Table والتلخيص.
- بيانات ChartQA تحتوي جداول مصدرية وتعليقات/صناديق لبعض الرسوم، لكنها ليست مجموعة شموع BTC موسومة بأنماط التداول.
- DePlot/UniChart لا يضمنان استخراج OHLC لكل شمعة أو تمييز wick/body أو دعم نمط TradingView الخاص.

**قرار مرصاد:** مرشحان لطبقة وصف/تحقق بصري مستقبلية فقط، لا لإنتاج أسعار أو شموع يعتمد عليها المحرك. لا نضيف أوزاناً كبيرة أو استدلالاً لغوياً إلى المسار الأساسي قبل إثبات القيمة.

## 3) مشاريع مالية متخصصة بالشموع — تُستخدم للمقارنة لا للنسخ

### ChartSense
- الرابط: https://github.com/Harsh-617/ChartSense
- الترخيص المعلن: MIT.
- يصف المشروع ResNet18 مع رأسي تصنيف للنمط والاتجاه وGrad-CAM للتفسير.
- README يذكر 3,000 صورة اصطناعية، وعلامات الأنماط متاحة للبيانات الاصطناعية فقط، و300 صورة حقيقية، و41.7% دقة اتجاه على البيانات الحقيقية ثلاثية الفئات. هذه أرقام المؤلف وليست تحققاً مستقلاً من مرصاد.
- المتطلبات تتضمن PyTorch وtorchvision وscikit-learn وmatplotlib وغيرها، أي اعتماد ووزن تشغيل إضافي.

**قرار مرصاد:** يستحق دراسة طريقة Grad-CAM والاختبار البصري لاحقاً؛ لا يصلح الآن بديلاً لمحللنا القائم على OHLC والقواعد، ونتيجة 41.7% لا تبرر إضافته لمسار قرار.

### Financial-Chart-Understanding-System
- الرابط: https://github.com/VT69/Financial-Chart-Understanding-System
- يعلن كشف 13 نمط شموع عبر YOLOv8 ودمج خصائص OHLCV للتنبؤ بنظام التقلب.
- بيانات GitHub API وقت البحث لا تعرض ترخيصاً؛ لا ننسخ الشيفرة أو الأوزان قبل إثبات الترخيص ومراجعة بيانات التدريب والاختبار.

**قرار مرصاد:** مرجع لأفكار الوسم والتجزئة والدمج، لا اعتماد برمجي حالي.

### image2ohlc
- الرابط: https://github.com/VeinDevTtv/image2ohlc
- README يصف خط معالجة TypeScript/Node وصور TradingView ويدعي خطأ تحويل صغيراً في الرسوم القياسية.
- GitHub API لا يعرض ترخيصاً للمستودع، ويبين أن آخر دفع كان 24 أكتوبر 2025 وعدد النجوم 1. لم نجد دليلاً مستقلاً منشوراً يثبت ادعاء الدقة على أنماط مرصاد.
- لا يجوز التعامل مع وصف المؤلف للدقة كاختبار محايد.

**قرار مرصاد:** لا ننسخ الشيفرة أو ندخلها كاعتماد بسبب غياب الترخيص المعلن وضعف دليل التحقق. يمكن استخدام حالات الاختبار والأفكار العامة فقط، لا الشيفرة.

### chart-vision-mcp
- الرابط: https://github.com/nessos666/chart-vision-mcp
- يعلن MIT وOpenCV/Tesseract محلياً، لكنه يصرح في README بأنه لا يكتشف أنماط الرأس والكتفين/المثلثات ولا يفسر أنماط الشموع مثل الدوجي والابتلاع والهارامي.
- يتقاطع مع بعض وظائفنا الحالية في كشف الخطوط/المستويات، ولا يضيف فجوة كبيرة للمحلل.

**قرار مرصاد:** لا حاجة لنسخ مشروع كامل يكرر قدرات موجودة ويعلن صراحة غياب تحليل الشموع.

## 4) مجموعات البيانات — منع الخلط بين الاختبار والتدريب

### Crypto-Chart-Dataset
- المصدر: https://huggingface.co/datasets/sogosonnet/Crypto-Chart-Dataset
- README يذكر 29,080 صورة تقريباً من 15 عملة مشفرة خلال 2015–2025، مع OHLCV مرسوم ومؤشرات MA/Bollinger وحجوم، وأسعار مطبّعة بالنسبة المئوية مع إزالة تدريجات المحور.
- مجموعة الاختبار التي استخدمناها سابقاً (10,474 صورة) جزء من هذا المصدر نفسه؛ لا تعد مجموعة مستقلة جديدة لمجرد إعادة تنزيلها.
- Labels مبنية على عوائد مستقبلية بفئات وعتبات محددة؛ هي ground truth لتقييم اتجاه لاحق، وليست ground truth بشرية لوجود المطرقة أو BOS أو Order Block.

**قرار مرصاد:** نستمر بها لاكتشاف أخطاء الاستخراج والمقارنة قبل/بعد، لكن لا ندرب قواعد الشموع أو نضبطها على مجموعة test ثم ندعي استقلالها. نحتاج مجموعة BTC بشرية موسومة منفصلة.

## 5) القرارات الهندسية المعتمدة بعد البحث

1. الإبقاء على قارئ OpenCV الحالي كمسار أساسي مؤقت، مع مسار slot-guided الذي أضيف حديثاً؛ لا نثق في أي نموذج خارجي قبل اختباره على لقطاتنا.
2. اعتماد فكرة Chart Extractor كمرشح metadata فقط: اكتشاف title/price pill ثم قراءة النص محلياً. لا يدخل السعر المقروء في معايرة المحور إلا بعد التحقق من مطابقته للتدريجات.
3. الاستفادة من ChartOCR في تصميم المعمارية الهجينة، لا إضافة DeepRule/CornerNet إلى requirements بسبب متطلبات GPU والتجميع وعدم تخصصه بالشموع.
4. عدم استيراد image2ohlc وFinancial-Chart-Understanding-System حتى تتضح تراخيصهما وتتوفر اختبارات قابلة لإعادة الإنتاج.
5. عدم إضافة ChartSense/UniChart/DePlot إلى المسار الأساسي الآن؛ يمكن اختبارها في بيئة جانبية لاحقاً لمساعدة الوسم أو التفسير، مع إبقاء OHLC ومعايرة الأسعار مرجعية منظمة.
6. ربط تحليل MTF في المحرك الثاني بقاعدة OHLC الحالية عبر قراءة فقط ومنصة أساسية واحدة؛ لا دمج بيانات المنصات ولا تغيير منطق المحرك الأول.
7. لا تتغير معادلة المحرك الرابع أو الأوزان بسبب أي من هذه التجارب.

## خلاصة البحث

أكثر ما يوفر الوقت الآن ليس تحميل نموذج كبير، بل الاستفادة من نموذج metadata صغير/اختياري عند الحاجة، والاستمرار في تطوير قارئ هجين متخصص بالشموع. المشاريع العامة تثبت وجود أدوات OCR وكشف عناوين/مناطق ورسوم، لكنها لا تقدم بديلاً جاهزاً ومثبتاً لاستخراج OHLC من كل شمعة BTC أو تحليل بنية السوق باعتمادية تداولية.


## 6) تدقيق إضافي لقواعد معرفة السوق والبيانات الموسومة

### CandleEdge — مرجع لتحليل التكرار التاريخي (MIT)
- الرابط: https://github.com/michaelsboost/CandleEdge
- GitHub API يعلن MIT. التطبيق مكتوب كتطبيق متصفح/JavaScript ويعتمد على بيانات CSV أو Coinbase، ويعرض كواشف لعدد كبير من الشموع والتكوينات البنيوية.
- وثائق الحساب تقيس العائد بعد 3/5/10/20 شمعة، وتستخدم عدد مرات الظهور لتقدير موثوقية العينة؛ هذا مفيد في تصميم طبقة إحصاء الأنماط في مرصاد.
- لكن الوثائق تصرح أن إحصاءاته لا تخصم السبريد والعمولة والانزلاق ولا تحسب drawdown أو Sharpe أو volatility. لا يستبدل محرك القرار أو محرك تقييم النتائج في مرصاد.
- Swing highs/lows عنده تقوم على local extrema بنطاق افتراضي ±3 شموع؛ هذا مرجع للمقارنة لا قاعدة عامة صالحة لكل سوق/فاصل.

**قرار مرصاد:** نستفيد من التصميم الوصفي المشروط بعدد العينات: لكل نمط/إطار/منصة احفظ عدد الحالات والعوائد بعد آفاق متعددة، وأظهر UNVALIDATED عندما لا تكفي العينات. لا ننسخ التطبيق أو نخلط احتمالاته مع أوزان المحرك الرابع.

### 4-Sight — ما الذي تعنيه فعلاً عبارة human-labelled OHLCV؟
- الرابط: https://github.com/stevesojan/4sight
- GitHub API لا يعلن ترخيصاً للمستودع وقت التدقيق؛ لذلك لا ننسخ ملفات أو شيفرة أو أوزاناً.
- المستودع يحوي مجلد human labelled ohlcv data/labels_json وفيه 1,219 ملف JSON وفق Git tree. العينة المفحوصة تحتوي ohlcv_data بعدد 300 شمعة، وحقل labels الذي يتضمن horizontal_lines وray_lines (مستويات أفقية وخطوط أشعة) مع الأسعار والتواريخ. هذه annotations مفيدة لدراسة مستويات السوق وخطوط الاتجاه، لكنها ليست في العينة وسوماً صريحة لأنماط الشموع مثل Hammer/Engulfing أو ground truth لنتائج BTC.
- ملف Pattern Identifier Annotated.py يولّد صور الأنماط باستعمال TA-Lib، ويضع صندوقاً حول شمعة النمط، ثم يحفظ image_labels.csv من اسم/نوع نمط TA-Lib. لذلك هذا الجزء من بيانات الصور rule-labelled، وليس وسم خبير بشري.
- لم نستنتج أن كامل مجموعة JSON موسومة بشرياً بصورة مستقلة من مجرد اسم المجلد؛ يلزم تدقيقاً أوسع في provenance والتعريفات ورخصة البيانات قبل إعادة الاستخدام.

**قرار مرصاد:** لا نستورد الملفات ولا نعتبرها تدريباً بشرياً لشموع BTC. يمكن استخدام وجود horizontal_lines وray_lines كفكرة لتوسيع نموذج تعليقات مستويات السوق لاحقاً، بعد بناء بيانات BTC خاصة بمرصاد أو إذن واضح.

### دراسة منفصلة تفصل كشف النمط عن أثره التنبؤي
- الرابط: https://github.com/Rohanjain2312/candlestick-pattern-recognition-system
- README يذكر أن صناديق التدريب تولدت من TA-Lib وليست annotations بشرية. كما يفصل السؤالين: هل تستطيع الرؤية تحديد النمط؟ وهل تضيف معرفة النمط فائدة تنبؤية خارج العينة؟
- النتائج المنشورة للمشروع لا تُظهر تحسناً ذا دلالة إحصائية في توقع اتجاه اليوم التالي على SPY من إضافة النمط المكتشف، وفق ما يذكره README. هذه نتيجة مشروعه وبياناته وليست حكماً عاماً على BTC.
- يشرح المشروع أيضاً أهمية الفصل الزمني والـembargo لأن نوافذ الصور المتجاورة تتداخل في معظم شموعها.

**قرار مرصاد:** نقيس precision/recall لقراءة الصورة مستقلة عن MAE/MFE/returns بعد النمط، ثم نختبر الأثر على BTC خارج العينة بفصل زمني يمنع تداخل نوافذ الشموع. لا نخلط جودة اكتشاف الصورة بالربحية.

### خلاصة الإضافة

أفضل استثمار قابل للتطبيق ليس إعادة استعمال بيانات غير متحقق من ترخيصها أو مصدر وسمها. هو بناء سجل إحصائي وصفي داخل مرصاد يحفظ تعريف النمط، شروط التأكيد والإبطال، سياق السوق، عدد العينات، والعوائد بعد 1/3/5/10/20 شمعة، ثم يضيف التكاليف عند اختبار أي فرضية تداولية. كل الحقول الإحصائية تبقى UNVALIDATED حتى تنتج من بيانات BTC فعلية واختبار خارج العينة.
