# مرصاد البيتكوين — Mirsad BTC

منصة مستقلة لتحليل البيتكوين بأربعة محركات فقط، مع بيانات سوق فعلية وقواعد تحليل قابلة للتدقيق ولوحة مراقبة عربية. لا يستخدم البرنامج نموذجاً توليدياً أو نموذجاً لاتخاذ قرار التداول؛ يتوفر OCR محلي لقراءة أرقام المحور فقط، ولا توجد أسعار مصطنعة أو صفقات محاكاة أو API مدفوع في المحرك الأساسي.

## ترتيب المحركات المعتمد

1. **المحرك الأول — السوق والمعلومات:** يجمع السعر والشموع بستة أطر زمنية (1m, 5m, 15m, 1h, 4h, 1d)، ودفتر الأوامر، والصفقات العامة وتدفق Taker من Binance Spot وBybit Spot وOKX Spot. يحفظ البيانات في SQLite. كل منصة تبقى معلّمة بمصدرها.
2. **المحرك الثاني — تحليل الرسوم والصور:** يحلل لقطة رسم حقيقية عبر وحدات مستقلة لسلامة الصورة، ومعايرة المحور الخطي/اللوغاريتمي، واستخراج الشموع، وبناء الاتجاه والبنية والزخم، والأنماط المرئية، وقياس جودة الأدلة. يمكن لـ RapidOCR المحلي قراءة تدريجات محور السعر تلقائياً؛ وهو لا يقرر الاتجاه ولا يغيّر بيانات الشموع. توفر اللوحة أيضاً إدخالاً يدوياً للرمز والإطار ونوع المحور والأسعار وحدود منطقة الرسم وعدد الشموع المتوقع. ترتبط معايرة الصورة ببصمة SHA-256 لمنع خلطها بصورة أخرى، ولا تدخل الصورة في القرار قبل اجتياز بوابات الجودة.
3. **المحرك الثالث — جسر التواصل مع MT5 والخبير:** قناة ثنائية الاتجاه عبر مجلد Common Files باسم MirsadBTC. يستقبل نبض الخبير والحساب ومواصفات الرمز والمراكز وإقرارات التنفيذ، وينقل إليه أوامر المحرك الرابع. لا يصنف نوع الحساب ولا يحسب المخاطر ولا يتخذ قراراً.
4. **المحرك الرابع — مركز اتخاذ القرار وإدارة المخاطر:** يستمد أدلة اتجاهه من المحرك الأول (السوق) والثاني (التحليل) فقط. يدمج قواعد EMA/RSI/ATR متعددة الأطر وتدفق الصفقات مع نتيجة الشارت المعاير، ويصدر BUY/SELL/WAIT. يستعمل بيانات الحساب ومواصفات الرمز التي ينقلها المحرك الثالث لحساب وقف الخسارة والهدف والحجم والمخاطرة؛ هذه المعلومات التشغيلية لا تصوّت على اتجاه الإشارة.

## مكونات المحلل البصري

المحرك الثاني موزع على `chart_image.py` لسلامة الصورة، و`chart_calibration.py` لمعايرة المحور، و`chart_extraction.py` لاستخراج OHLC، و`chart_patterns.py` للمرشحات الشكلية، و`chart_pattern_reference.py` لمقارنة تعريفات الأنماط الحسابية بواسطة TA-Lib على OHLC المعاير، و`chart_metrics.py` للاتجاه والبنية والزخم وجودة الأدلة، و`chart_ocr.py` لقراءة تدريجات السعر. يبقى `chart.py` نقطة الدخول الموحدة. يستخدم OCR نموذجاً محلياً لقراءة النص فقط؛ لا يصدر قرارات. لا يعتمد السعر الآلي إلا بعد أربع تدريجات متمايزة وملاءمة متناسقة، وإلا يجب إدخال نطاق السعر يدوياً. تقارن وحدة TA-Lib أكثر من 60 تعريفاً للأنماط على OHLC المعاير وتعرض حالات التكوين/الاكتمال/الإبطال منفصلة عن المرشحات الهندسية المستخرجة من الصورة؛ ولا تتحول درجات TA-Lib إلى احتمالات نجاح. مؤشر الثقة قيمة إرشادية لجودة الأدلة وليس احتمالاً إحصائياً، والأنماط لا تصوت على اتجاه المحرك الرابع.

## شكل الربط

المحرك 1 + المحرك 2 ← مركز القرار (المحرك 4) → جسر التواصل (المحرك 3) ↔ خبير MT5

التفصيل في ملف التصميم المعماري وملف بروتوكول MIR1.

## التكامل الحالي

- Engine 1 → Engine 4: موصول.
- Engine 2 → Engine 4: موصول؛ ويشترط تطابق الرمز والإطار والمعايرة السعرية.
- Engine 3 ↔ Engine 4: قراءة حالة الجسر من جهة البرنامج وإرسال أوامر MIR1 من المحرك الرابع واستقبال الإقرارات ومعلومات المراكز.
- Engine 4 → Engine 3: نشر أوامر MIR1 مفعّل وفق تفويض المستخدم، مع معرف ثابت لمنع التكرار، ومنع استبدال أمر قيد الانتظار قبل تسوية إقراره.
- لوحة Streamlit تعرض المحركات الأربعة وتغذية السوق والتحليل والقرار والمخاطر وحالة الجسر، وتتحدث دورياً.

## مصادر السوق

- Binance Spot: https://developers.binance.com/en/docs/products/spot/rest-api
- Bybit V5: https://bybit-exchange.github.io/docs/v5/market/tickers
- OKX V5: https://www.okx.com/docs-v5/en/

المصادر العامة قد تحجب بعض المناطق أو عناوين IP. يظهر ذلك OFFLINE، ولا تُنشأ بيانات بديلة.

## التشغيل على Windows

داخل مجلد Mirsad_BTC:

    py -3.11 -m venv .venv
    .venv\Scripts\Activate.ps1
    python -m pip install --upgrade pip
    pip install -r requirements.txt

نافذة أولى: python run_mirsad.py
نافذة ثانية: streamlit run dashboard.py

ارفع صورة الشارت من اللوحة وأدخل أعلى وأدنى سعر ظاهرين على المحور. شغّل runtime قبل فتح اللوحة.

## أوامر التنفيذ وإدارة المركز

الخبير التنفيذي يستقبل BUY/SELL/CLOSE فقط من المحرك الرابع عبر الجسر الثالث. لا يولد إشارات من OnTick، ولا يصنف نوع الحساب، ولا يحسب المخاطر. إذا ظهرت إشارة معاكسة لمركز قائم يرسل المحرك الرابع CLOSE لتذكرة محددة أولاً؛ وبعد تأكيد الإغلاق يمكنه إصدار أمر عكسي لاحق. تُرفق مستويات الوقف والهدف والحجم المحسوبة داخل البرنامج بأوامر الفتح.

إعداد النشر الافتراضي أصبح مفعلاً استناداً إلى تفويض المستخدم، ويمكن تعطيله بمتغير البيئة MIRSAD_ENABLE_ORDER_PUBLISH=0. فحوص GitHub Actions لا تنشئ command.json ولا ترسل صفقة؛ وهي تقتصر على التجميع والتحقق من نبض الخبير.

## جودة ربط السعر والتنفيذ

لا يكفي تطابق اسم الرمز وحده؛ يجب أن يكون سعر MT5 حديثاً وقريباً من السعر الوسطي لمصادر السوق، وألا يتجاوز فرق السعر 1% أو السبريد 0.3% وفق الإعداد الافتراضي. يحاذي المحرك الرابع الدخول والوقف والهدف مع tick size وdigits ومستوى الوقف الأدنى لدى الوسيط، ثم يحسب الحجم على مسافة الوقف النهائية. يمكن ضبط الحدين عبر MIRSAD_MT5_MARKET_DIVERGENCE_MAX_PCT وMIRSAD_MT5_MAX_SPREAD_PCT.

توجد اختبارات وحدات لعقود الحجم والجسر ومعرفات MIR1 وملكية المراكز في Mirsad_BTC/tests. اختبارات CI لا تنشئ أوامر تداول ولا تحاكي صفقات.

## ملف خبير القراءة فقط القديم

الملف `mt5/BitcoinIntelligence_ReadOnlyBridge.mq5` محفوظ كمرجع تاريخي للإصدار الأول. لا يستخدمه البرنامج التنفيذي الحالي. سير عمله أصبح يدوياً فقط، أما البناء النشط فيستخدم `mt5/Mirsad_BTC_ExecutionBridge.mq5` عبر `mirsad-btc-mt5-execution.yml`.
