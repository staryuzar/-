# المساعد الذكي — Aurora Control Room

واجهة عربية لمساعد محلي يجمع المحادثة، الذاكرة المحلية، أدوات Windows، التحكم في Chrome، وإجراءات اختبار المشروع.

## حالة التحقق

- فحص الحزمة الأصلية قبل أي تعديل: 73 ملفًا داخل الأرشيف.
- اكتُشفت علامة UTF-8 BOM في `DIAGNOSE_WINDOWS.bat`؛ النسخة المصححة تزيلها وتعيد توليد ملف بصمات SHA-256.
- أضيف إصلاح يحفظ محتوى الحافظة ويعيده بعد البحث عن علامة Chrome أو قراءة الصفحة، حتى عند فشل العملية.
- أضيف اختبارا انحدار لمحاكاة استعادة الحافظة بعد النجاح والاستثناء.
- آخر مجموعة تحقق مكتملة: Windows Server 2022 مع Python 3.11 و3.13؛ **225 اختبارًا و122 حالة فرعية ناجحة لكل إصدار**. هذا تحقق آلي للشفرة والاختبارات، وليس شهادة تشغيل تفاعلي على كل جهاز Windows أو إثباتًا لاتصال Gmail/MT5.

## اختبارات التكامل الأخيرة — 2026-10-19

- **واجهة المحادثة:** شُغّلت Streamlit على Windows Server 2022، وأعاد مسار الصحة `/_stcore/health` والصفحة الرئيسية HTTP 200.
- **Chrome الفعلي:** نجحت 7 من 7 فحوصات على متصفح Chrome حقيقي مع صفحة اختبار مؤقتة: قراءة النص، النقر على زر فريد والتحقق من النتيجة، رفض حقل كلمة المرور، رفض الأزرار الملتبسة، رفض عنوان تصحيح بعيد، وحظر عنوان localhost من مسار التصفح العام.
- **MetaTrader 5:** نُزّلت المنصة الرسمية إلى مجلد CI مؤقت. ظهر الملف `terminal64.exe` بالإصدار `5.0.0.6272`. شغّلتها أداة `windows_tools.launch_program` نفسها، وتأكد الاختبار من استمرار العملية 15 ثانية. استطاعت أداة واجهة Windows اكتشاف نافذة `MetaTrader 5 - Netting - EURUSD,H1` وقراءة عناصرها، ثم النقر على `Cancel` في نافذة «فتح حساب» والتحقق من بقاء النافذة الرئيسية واختفاء الحوار.
- **ملاحظة مثبتة:** أعاد مُثبّت MT5 رمز خروج `1` رغم أن الملف التنفيذي وُجدا والمنصة اشتغلت وفُحصت واجهتها. لا نتجاهل هذا الاختلاف؛ يُسجل كتعارض في رمز المُثبّت، بينما نجاح اختبار التكامل يعتمد أيضًا على وجود الملف وتشغيله والتحقق من الواجهة.
- **اختبارات الحزمة:** نجحت `225` اختبارًا و`122` حالة فرعية على كل من Python 3.11 و3.13 في آخر تشغيل مكتمل.
- **حدود الاختبار:** لم يتم تسجيل الدخول إلى وسيط أو حساب تجريبي. جُمّع مستشار تجريبي مؤقت عبر MetaEditor بنجاح (0 أخطاء و0 تحذيرات)، لكن لم يُترجم مستشار المستخدم نفسه، ولم يُشغّل Strategy Tester ولم تُفتح صفقات. كذلك لا يثبت اختبار أدوات المتصفح أن جلسة Gmail الشخصية للمستخدم قد اختُبرت. اختبار استدعاء نموذج اللغة من OpenRouter لم يُنفّذ ضمن CI؛ فشل الحصة المجانية `429 free-models-per-day` كان عائقًا سابقًا، ويجب اختبار مسار المزوّد منفصلًا عند توفر حصة.

## الحصول على الحزمة المصححة

1. افتح تبويب **Actions** في هذا المستودع.
2. افتح أحدث تشغيل ناجح لسير العمل **Aurora Windows validation**.
3. من قسم **Artifacts** نزّل `Aurora-Control-Room-v2.4.0-patched`.
4. الأرشيف الذي بداخله هو حزمة ZIP المصححة، مع ملف بصمات SHA-256 محدث.

الحزمة الأصلية محفوظة كما هي كمدخل تدقيق؛ الإصلاحات تُطبّق بصورة قابلة للتكرار على نسخة البناء، ولا تُخفى تغييرات الاختبارات خلف تعديل صامت للأرشيف الأصلي.

## تطوير واختبار آمن

- تُختبر التغييرات على نسخة مستخرجة من الحزمة الأصلية، ثم تُبنى حزمة مصححة منفصلة.
- لا تضع كلمات مرور حساباتك أو مفاتيح API أو ملفات `.env` الفعلية في GitHub.
- لا تعني نتيجة الاختبارات الآلية أن تسجيل الدخول إلى خدمات شخصية أو تنفيذ إجراءات مالية قد اختُبر. يجب أن تبقى اختبارات الحسابات المالية في بيئة تجريبية، مع التحقق من النتائج بدل افتراض نجاح النقرات.
- تفاصيل الإصلاحات في `PATCH_REPORT_AR.md`، وخطوات التحقق في `.github/workflows/windows-validation.yml`.
